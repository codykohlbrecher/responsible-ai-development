# Guidelines for Responsible AI-Assisted Software Development

## Overview

Over the past few years AI coding tools have become an integral aspect of the software development cycle. These tools can be used for many things such as generating code, debugging, writing tests, and helping developers understand unfamiliar technologies. From my own experience using tools like Codex and Claude Code, I have found them to be extremely useful when working on both personal and school projects.

With that being said, I also think that there are some concerns to address. 
Developers who use these tools should refrain from relying too heavily on AI-generated solutions. Develoeprs should always fully understand how each part of the code base works. This is especially important when working on team projects since your fellow developers are often going to assume that you have a complete understanding of your code. 

These guidelines are not supposed to discourage developers from using these tools, that would be unrealistic. Instead these guidlines are designed to create practical standards that can help developers use AI tools to write code responsibly. 

These guidelines are primarily intended for junior developers and UCSB Computer Science students working on team-based programming projects.

---

## 1. Human Accountability

Developers should always remain responsible for the code that they submit regardless of whether AI assistance was used.

As AI coding agents become more and more capable of completing programming tasks, it is becoming easier to delegate more work and thinking to them. Allthough it may be easier and faster to allow the AI agents to work with more scope, developers are always going to be held responsible for the output and should always understand and be able to explain their code.

For example, if a student uses AI to complete a GitHub issue and the generated code ends up introducing a bug, blaming the fault in the code on an AI agent means nothing. At the end of the day an agent is not a person and all of the responsibility is going to fall on the developers who approved the changes. 

**Guidelines:**

- Developers should take responsibility for all code that they include in Pull-Requests, including code generated by AI.

- AI-generated implementations should be thuroughly reviewed before being committed.

- Developers should always be able to explain the decisions made in their implementations.

- AI assistance should never be used as an excuse for any bugs, errors, or vulnerabilities introduced into your code. 

---

## 2. Understand Before You Merge

One of the biggest problems that I want to address is developers accepting AI-generated code without actually understanding how it works.

From my own experience I know how easy it can be to ask an AI coding tool to fix a problem and then accept the solution once the tests begin passing. However, just because a solution works does not necessarily mean that the developer understands what the code is doing.

In my CMPSC 156 class we work in development teams and regularly submit pull requests that other students have to review. If a student is not able to explain the code that they are submitting then it can become much more difficult to find and fix bugs or vulnerabilities. 

**Guidelines:**

- Developers should ALWAYS be able to explain what their generated code does and why it works.

- Before submitting a PR, developers should review all or most changes made by the agent. 

- If the AI generates an unfamiliar approach, developers should take the time to understand them.

- If a developer cannot explain any part of their implementation, they should investigate it or rewrite it before merging.

My general rule is that **developers should never merge code that they cannot UNDERSTAND, EXPLAIN, and DEFEND**.
---

## 3. Passing Tests Does Not Guarantee Reliable Code

Another important concern with AI-assisted development is the assumption that passing automated tests automatically means that the generated code is correct.

Automated testing is a useful aspect of the development process and can help spot bugs early. However from my own expirience in web development these automated tests do not always catch every bug or expose every vulnerability. AI tools may generate tests that do not handle every edge case or possible input. It is also possible that AI creates the tests and implementation with incorrect assumptions about the goals of the project. 


This is why I think developers should never rely on automated tests, especially tests generated by AI, to verify an AI generated solution. 

**Guidelines:**

- Developers should run the available tests before submitting AI-assisted changes.
- Passing tests should not be the only reason that a pull request is approved.
- Developers should review the generated implementation to make sure that it actually solves the original problem.
- Important edge cases such as missing data, invalid inputs, and unexpected behavior should be considered.
- If AI was used to generate tests, developers should independently review what those tests are actually checking.


---

## 4. Security and Code Verification

In a researched study provided in the research section of this repository, researches had found that developers who used AI tools ended up generating code with more vulnerabilities while being more confident in their solutions. This is concerning since AI assisted cyber attacks are becoming more common.

I have developed a few guidlines to for junior developers to help avoid flaws and vulnerabilities that can be exploited. 

**Guidelines:**

- Developers should manually scan and check AI-generated code for potential security vulnerabilities.

- User input should be properly validated when necessary to avoid SQL injections. 

- Passwords, API keys, and other sensitive information should never be exposed in generated code or committed to a repository.

- Developers should verify that AI-generated changes do not introduce extra security risks.

- Security checks should be appropriate for the project and the potential consequences of a mistake.



---

## 5. Transparency in AI Usage

As we have discussed, AI tools can often generate vulnerable or sub-optimal solutions. This makes it very important to document what parts of your code AI assistance was used. 

Developers do not have to document every single prompt that they use, that would be unrealistic. However sections of code that were developed with the assistance of AI should be documented so that developers and reviewers know to heavily scrutinize those areas. This will allow team members to thuroughly review AI generated sections of the code base so they can enhance their understanding and reduce flaws. 



**Guidelines:**

- Developers should be open about any significant AI assistance used in their work.

- PR descriptions should mention which parts of an implementation were generated or modified with AI.

- Developers should explain what they personally reviewed and tested before submitting the changes.


---

## 6. AI as an Assistant, Not a Replacement

AI should always be used to enhance your understanding, implementation, or workflow. It should not replace it.  Throughout my research I found that AI can provide significant enhancements in regards to developer productivity in certain situations. But as discussed, I also found research suggesting that AI does not necessarily make developers more productive in every development environment. This makes it important to understand where to use AI as a worker, assistant, and where to never use it. 



**Guidelines:**

- Developers should consider whether AI assistance is actually beneficial for the task they are completing.

- AI can be useful for generating initial implementations, debugging, explaining unfamiliar code, and suggesting tests.

- Developers should not automatically accept the first solution that an AI tool generates.

- Developers should continue developing their own programming skills along side their usage of AI. 

- The final decisions about an implementation should be the responsibility of human developers. 


---


## Final Takeaway

Overall, I believe AI coding tools have the potential to be extremely useful resources for software developers. However, I also think that it is important for developers to understand the responsibilities that come with using these tools.

My goal with these guidelines is not necessarily to establish a strict set of rules that every software developer must follow. Instead, I want to provide junior developers with practical recommendations that encourage responsible AI usage.

At the end of the day I believe that developers should always remain capable of understanding, explaining, and defending the code that they produce, regardless of whether they wrote it themselves or generated it with AI assistance.
