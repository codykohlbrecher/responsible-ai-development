# Human-in-the-Loop Workflow for AI-Assisted Software Development

## Overview

This workflow is intended to provide a practical, easy to follow process that junnior developers and students can follow while using AI tools to help write software. 

## The Workflow

**Understand the Issue → Use AI Assistance → Review the Code → Test and Verify → Submit a Pull Request → Human Review → Merge**

### 1. Understand the Issue

The first step a developer should take is develop a thorough understanding of the task they are trying to accomplish. Developers should attempt to create a plan before immediately asking AI to generate a solution

**Human Checkpoint:** Am I able to explain what the issue is asking me to implement?

### 2. Use AI Assistance

Developers should first decide where AI is useful and where it could lead to problems. This could include writing code, debugging, or explaining problems to or for the developer. 

**Human Checkpoint:** Is using AI for each subtask going to save me time or cost me time?

### 3. Review the Generated Code

After AI generates an implementation the developer should personally review the changes. Just because the code looks correct does not necessarily mean that it is appropriate for the project.

**Human Checkpoint:** Can I understand, explain, and defend the code that was generated?

### 4. Test and Verify

Developers should write their own tests, have AI generate tests, and check that the program behaves as expected. However even if all of these tests pass, you can not garuntee that the code is up to standard and ready to be merged into a PR. 

**Human Checkpoint:** Have I checked for issues in the code that automated tests may have missed?

### 5. Submit a Pull Request

Once the developer understands the code, has reviewed it, and tested it, they may submit a pull request. The description should include what testing you did, an explanation of the changes made, and documentation of which parts of the PR were created with AI assistance. 

**Human Checkpoint:** Can another developer understand what I changed and how I verified it?

### 6. Human Review

Before merging a PR it is imperitive that multiple other team members review the changes made. The other developers should understand the new code and should have checked for bugs and or vulnerabilities. 

**Human Checkpoint:** Does the reviewer understand the changes and have any concerns been addressed?

### 7. Merge

Once most of the developer and the rest of the team can understand the code and are confident that it does not introduce bugs or vulnerabilities then it is safe to merge!

## Final Takeaway

This workflow is designed to make sure that software developers can maintain their understanding and responsibility of code that is generated by AI. AI coding agents should be used as a tool rather than a crutch for developers.
